Keycloak App

Client de test OIDC complet : authorization code + PKCE contre un Keycloak (ou tout autre IdP OIDC). Login, affichage des tokens, userinfo, refresh, logout — équivalent local de https://www.keycloak.org/app/, 100% navigateur.

Configuration

Connexion au Keycloak

Déconnecté

Le client doit être configuré en public (Access Type: public) côté Keycloak, avec Standard Flow Enabled et l'URL de cette page ajoutée aux Valid Redirect URIs et Web Origins (sinon CORS bloquera l'échange du code contre les tokens).

Données stockées : sessionStorage uniquement
Erreur

Profil utilisateur

Synthèse des claims standard du id_token. Clique sur User info ci-dessus pour interroger le endpoint /userinfo et comparer. 


        

      


      

        

          
Access token

          
        

        

          Token envoyé en header Authorization: Bearer ... aux API protégées.
          Souvent un JWT côté Keycloak (mais pas garanti — l'IdP peut renvoyer un token opaque).
        

        

        

          
          

        

        

          
          

        

        

          

        

      


      

        

          
ID token

          
        

        

          Identité de l'utilisateur (claim sub) et de la session.
          À valider côté client selon OIDC Core §3.1.3.7 (voir tool ID Token Validator).
        

        

        

          
          

        

        

          
          

        

        

          

        

      


      

        

          
Refresh token

          
        

        

          Permet d'obtenir un nouvel access_token sans relogin (grant_type
          refresh_token). Format opaque dans la version par défaut de Keycloak.
        

        

        

          
          

        

      


      

        

          
Réponse brute du token endpoint

          
        

        

          JSON tel que renvoyé par POST /token. Utile pour debug
          (expires_in, refresh_expires_in, session_state...).
